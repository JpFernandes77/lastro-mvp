# User Journeys

> **Status:** working product specification. This document operationalizes the current thesis; it does not establish validated market facts.

## Purpose

Describe the minimum journeys through which the product connects organizational need, competency development, evidence, verification, state and exceptional adjudication.

## Primary journey

~~~text
ORGANIZATION
  ↓
Competency desired
  ↓
Short trail
  ↓
PERSON
  ↓
Activities
  ↓
Evidence
  ↓
Independent verification mechanisms
  ↓
Consensus Core
  ↓
Competency state
  ↓
Human adjudication only when necessary
  ↓
Attestation
  ↓
Verification
~~~

## Organization

1. Identify a competency need.
2. Define the desired competency.
3. Configure a short development trail.
4. Observe evidence produced during the trail.
5. Inspect the interpreted evidence and verification context.
6. Register a resulting competency state when the defined criteria are met.
7. Issue an attestation when the MVP flow supports it.
8. Allow an authorized verifier to inspect the proof.

## Person

1. Enters a defined trail.
2. Performs activities.
3. Produces evidence linked to those activities.
4. Receives structured interpretation of the evidence.
5. May receive adjudication only when the verification process cannot resolve a material conflict, ambiguity or contestation.
6. Progresses through defined competency states.
7. Can use the resulting attestation as a verifiable representation of the recorded state.

## Adjudicator — exception path

1. Receives the verification context only when adjudication is required.
2. Distinguishes source material from AI inference.
3. Examines conflicting, ambiguous or contested evidence.
4. Records the adjudication context.
5. Resolves the case according to the defined governance rules.

## Verifier

1. Receives an attestation reference.
2. Resolves the subject, competency and state represented.
3. Checks the attestation and relevant integrity data.
4. Uses only the information the verification mechanism actually supports.

## MVP boundary

The journey must remain demonstrable with one competency, one short trail, one person, limited evidence formats, assisted AI interpretation, independent verification, human adjudication only as an exception, a persisted state, an attestation and a verification path.

This document does not define recruiting, marketplace, LMS replacement, universal credentialing or broad institutional integrations.
